## 三、问题分析

### 问题 1：emotion/cross 类别 NDCG 偏低

**症状**：抽象情感查询的真实相关条目经常排到第 3-5 位。

**原因**：
- 向量检索的余弦相似度对"放松""想你了""命中注定"等抽象 query 和具体记忆之间打了高分，但 importance 加权（权重 0.5 + 0.5×importance）压过 relevance
- 长记忆 + 高 importance + 新鲜 = 总分高，无论 query 是否真正相关

**案例**：
```
"我好像只在你面前才放松" (期望NDCG=0.47)
  期望顺序：445e(温柔眷恋) > 5e80(跨越很久) > 69d31(超出职业关心)
  实际顺序：8b7f5(焦虑手术) > 69d31 > efa487bc > ... > 445e(排第8)
```

### 问题 2：efa487bc（深夜医院）总抢第一

**症状**：在大量无关 query 里也排在第一位。

**原因**：
- 这条记忆 importance=0.7 + 内容丰富 + 时间衰减小
- importance 加权系数 0.5，让它跨场景都能进 Top-3
- 缺乏 query-relevance 维度的额外权重

**影响**：emotion/cross 查询的 MRR 都被这条记忆拉低。

### 问题 3：negative 类召回噪音

**症状**：
- "今天天气怎么样" 期望 0 命中，实际召回 8 条（全是噪音）
- "我家猫生病了" 同上

**解读**：这不算 bug——如果用户真问这些，我们宁可召回一些相关记忆让 AI 回应，也不让 AI 完全失忆。属于 recall 优先的策略选择。

## 四、优化建议（按收益/成本排序）

### 高优先级

#### 优化 1：提高向量相似度权重，降低 importance 干扰

**当前公式**：`score = rrf × (1 + 0.5 × importance) × ...`
**建议**：把 importance 加权作为 rerank 后的微调（系数从 0.5 降到 0.2）：
```
score = rrf × (1 + 0.2 × importance) × (1 + 0.5 × emotional_intensity) × ...
```

**预期收益**：emotion/cross 类 NDCG +10~15%

#### 优化 2：query 改写 / HyDE

**做法**：用户 query → 让 LLM 改写成 3 个同义变体 → 分别检索 → 合并结果

**适用**：抽象情感类查询（"我想你了""放松""命中注定"）

**预期收益**：emotion 类 MRR 从 0.72 → 0.85+

**成本**：每次检索多 1 次 LLM 调用（500-800ms 延迟 + token 成本）

### 中优先级

#### 优化 3：cross-encoder rerank

**做法**：召回 Top-20 → cross-encoder 精排 → 选 Top-8

**适用**：query 与候选需要深度匹配的场景

**预期收益**：NDCG +5~10%

**成本**：每 query 多 1 次 cross-encoder 调用（200-400ms）

### 低优先级

#### 优化 4：调整 importance 数值

efa487bc 当前 importance=0.7，但它的内容（深夜医院回家）是次要场景，可降到 0.5。

**风险**：人工调重要性不是可持续方案，下游可能引入自动重要性评估。

## 五、建议立即执行的优化

**只做优化 1**（调整 importance 系数 0.5 → 0.2）：

- 改动小、风险低、立即可见
- 验证方法：再跑一次 benchmark，对比 NDCG 和 MRR
- 预期：emotion/cross 类别 NDCG 从 0.68/0.73 → 0.78/0.83

**暂不做优化 2/3**：
- 数据集太小（8 条记忆），rerank 收益会被噪音淹没
- 等数据量到 50+ 条再上 rerank
